## Context

前兩個 change 建好了 discovery／view 的邊界與樹的呈現。本次三件事全部落在 view 這一側：篩選、複製、送出指令，discovery 完全不動。

這也是三項移植裡最不對稱的一段。前兩個 change 的需求幾乎能逐條照搬 JetBrains 版，本次三項各自撞到一個 VS Code 沒有對應物的設施：tree view 沒有可放輸入框的位置、擴充無法攔截樹的標準 Copy 動作、選單的標題與項目文字在 manifest 裡都是靜態的。三個限制各需要一個決策，而三個決策都不影響既有的模組邊界。

檢視標題旁目前已被排序狀態佔用（`Sort: Modified`），篩選狀態要共用這塊空間。

## Goals / Non-Goals

**Goals:**

- 三項行為的純邏輯（比對、選取集合轉文字、指令文字組裝）都不 import `vscode`，能用 Vitest 完整覆蓋。
- 篩選期間群組節點同時給出符合數與總數，讓被篩掉的變更不會被誤讀為不存在。
- 送出指令永遠不執行它，且選錯終端機的代價可回復。

**Non-Goals:**

- 常駐篩選輸入框、webview、內建型別搜尋。
- 沒有終端機時自動開一個、自動執行指令。
- 讓提案人參與篩選比對。
- 持久化篩選字串或排序選項。

## Decisions

### 篩選以指令搭配輸入框驅動，狀態顯示於檢視標題旁

標題列一個篩選按鈕開啟輸入框，輸入的文字成為目前篩選；清空即取消篩選。目前篩選字與排序選項共用檢視標題旁那塊文字，形如 `Sort: Modified · Filter: search`，沒有篩選時只顯示排序。

替代方案有兩個，都已否決。webview 能做常駐輸入框，但要自行重寫樹狀渲染、主題與鍵盤操作，成本是它換來的那一項便利的數倍。編輯器內建的樹型別搜尋不需要任何程式碼，但它比對的是整個節點文字 —— 提案人與進度數字都會被誤中 —— 而且群組節點無法藉此顯示符合數與總數。

代價是篩選不再是「邊打邊縮」，而是「輸入後套用」。這是本次唯一一處明確偏離參考外掛行為的地方。

### 群組節點在篩選期間顯示符合數與總數

沒有篩選時群組節點顯示變更數量。有篩選時改為同時顯示符合數與總數，例如三個之中符合一個。

這條規則存在的理由是防止誤讀：只顯示符合數的話，一個空的 Active 群組無法區分「沒有變更」與「有變更但都被篩掉了」。

### 複製走自訂指令與鍵盤繫結，而非標準 Copy 動作

VS Code 沒有讓擴充攔截樹狀 Copy 的 API，所以複製由一個自訂指令承擔，並在右鍵選單與鍵盤繫結上各出現一次，繫結條件限定焦點在本檢視時。多選靠檢視的多選選項開啟，指令從參數取得整個選取集合。

選取集合轉文字的規則獨立成純函式：只取變更節點，群組與 artifact 節點忽略而非阻擋，多個名稱以單一換行分隔，順序依樹上由上而下。沒有任何變更節點時不寫入剪貼簿，讓剪貼簿內容維持原樣。

複製的內容是變更名稱本身 —— 不含群組、不含提案人、不含進度數字。節點上顯示的裝飾資訊都不該跟著貼出去。

### 指令文字是單行，且永遠不附換行

指令文字為斜線指令名、一個空格、變更名稱，沒有結尾換行。寫進終端機時因此停在輸入位置等待使用者按 Enter。

不自動執行有具體理由：使用者可能選錯終端機分頁，或該分頁正跑著別的東西。停在輸入位置時，選錯的代價是一行可以刪掉的文字；自動執行的代價則無法預期。

### 沒有作用中的終端機時退回剪貼簿，不自動開新的

有作用中的終端機時寫進去並聚焦過去；沒有時把同一段文字寫進剪貼簿，焦點不動、不出通知。

替代方案是自動開一個終端機。已否決：新開的終端機位於工作區根目錄、使用預設 shell，未必是使用者原本所在的目錄或環境。把指令貼進一個位置不對的終端機，比讓使用者自己貼一次更糟。

### 以 QuickPick 呈現四個完整指令文字與當下去向

右鍵選單只放一個項目，選它開啟一個 QuickPick，列出四個**已經帶上變更名稱的完整指令文字**，標題明示接下來是寫進終端機還是寫進剪貼簿。

參考外掛讓同一個 submenu 依終端機是否可用改變標題，且每個項目顯示它會產生的完整指令。VS Code 的選單無法做到任何一項：`contributes.submenus` 的標題與 `contributes.commands` 的項目標題都是 manifest 裡的靜態字串，而變更名稱要到使用者右鍵當下才知道。

先前考慮過用兩個標題互補的 submenu 搭配一個 context key 來解決標題問題。已否決：它只解決標題，項目文字仍然顯示不出變更名稱，而 spec 要求「使用者讀到的就是這個項目會送出的東西」。QuickPick 兩者都能滿足，而且更簡單 —— 一個指令取代四個、零個 submenu 取代兩個、不需要追蹤終端機狀態的 context key 與其事件監聽。

代價是多一次點擊：右鍵之後還要在 QuickPick 裡選。換來的是使用者在按下去之前，看到的就是完整的那一行指令。

### 送出指令只在剛好選中一個變更節點時啟用

選取集合裡剛好有一個變更節點時啟用，群組節點與 artifact 節點忽略而非阻擋計數 —— 與複製對待它們的方式一致。沒有變更節點或超過一個時停用。

複製可以一次處理多個名稱，因為多行文字是合理的剪貼簿內容；指令則不行 —— 把兩個變更名稱接在同一個斜線指令後面不構成有效指令。

## Implementation Contract

**行為**

檢視標題列多一個篩選按鈕，按下開啟輸入框。輸入文字後，三個群組同時只留下名稱含該文字的變更（不分大小寫），群組節點顯示形如「符合數／總數」的計數，標題旁的文字補上目前篩選字。清空輸入即恢復完整清單。符合的變更其 artifact 全部保留，artifact 路徑不參與比對。

選取一或多個變更節點後按複製鍵或用右鍵選單，剪貼簿得到那些變更的名稱，每行一個，順序與樹上由上而下一致。成功複製不出任何通知。

右鍵選單在剛好選中一個變更節點時提供一個項目，選它開啟 QuickPick，內含四個項目，每個項目的文字就是它會產生的完整指令。有作用中終端機時 QuickPick 標題為送出，選取後寫進該終端機輸入位置並把焦點移過去，指令不執行、剪貼簿不變；沒有時標題為複製，選取後把同一段文字寫進剪貼簿，焦點不動、不出通知。

**介面與資料形狀**

篩選模組匯出一個判斷變更是否符合的純函式，以及一個由完整清單與篩選字算出符合清單的函式，不接觸檔案系統與 VS Code API。

選取模組匯出一個把節點陣列轉成剪貼簿文字的純函式，回傳空值代表不應寫入剪貼簿。

指令模組匯出四個支援的斜線指令名，以及一個由指令名與變更名稱組出單行文字的純函式。

貢獻的識別碼：一個設定篩選的指令、一個複製的指令、一個開啟指令 QuickPick 的指令、樹的右鍵選單項目，以及一個鍵盤繫結。檢視需開啟多選。

**失敗模式**

- 篩選字沒有任何變更名稱包含：三個群組節點都出現，各自顯示零符合與其總數，其下沒有變更節點。
- 選取集合裡沒有變更節點：剪貼簿內容不變，不出通知。
- 選取集合含群組或 artifact 節點：那些節點被忽略，其餘變更名稱照常複製。
- 沒有作用中終端機：指令文字寫進剪貼簿，焦點不動，不出通知。
- 寫入終端機時拋出例外：錯誤記入輸出頻道，指令文字改寫進剪貼簿，不出對話框。

**驗收標準**

- Vitest 涵蓋：篩選的三群組同時套用、不分大小寫、artifact 不參與比對且全部保留、無符合時三群組皆在；群組計數在有無篩選下的兩種形式；選取集合轉文字的對照表（單一、多個、群組、artifact、混合、空選取）；四個指令的文字對照表與「無結尾換行」。
- manifest 測試涵蓋：篩選與複製指令存在、四個送出指令存在、開啟指令 QuickPick 的指令存在且出現在樹的右鍵選單、鍵盤繫結限定於本檢視焦點。
- 型別檢查零錯誤，esbuild 產出 bundle，打包指令產出 `.vsix`。
- Extension Development Host 手動驗證：輸入篩選字後三群組同時縮減且計數變為兩段式；多選兩個變更後複製得到兩行名稱；在有終端機與關閉全部終端機兩種狀態下各開一次右鍵選單，確認標題與去向相符，且送出後指令停在輸入位置未被執行。

**範圍邊界**

**在範圍內**：篩選及其計數呈現、複製選取的變更名稱、四個 Spectra 指令的 QuickPick、送出與剪貼簿退路、對應的 manifest 貢獻與鍵盤繫結。

**在範圍外**：Non-Goals 列出的全部項目。特別是不動 discovery 層、不動節點 id 規則、不動排序規則 —— 篩選在排序之後套用，兩者互不知道對方存在。

## Risks / Trade-offs

- **篩選改為「輸入後套用」，與參考外掛的即時縮減不同** → 這是 tree view 沒有輸入控制項的直接後果，且已在 spec 中寫明。標題旁持續顯示目前篩選字，使用者不會忘記自己正在篩選狀態。
- **鍵盤繫結搶用複製鍵，可能與使用者既有設定衝突** → 繫結條件限定焦點在本檢視時才生效，其餘情境完全不受影響；使用者也能在鍵盤快速鍵設定裡覆寫。
- **QuickPick 比 submenu 多一次點擊** → 換來的是項目文字與標題都是當下真實狀態，而非 manifest 裡寫死的近似值；使用者按下去之前看到的就是完整那一行。
- **QuickPick 的標題在開啟當下決定，開著的期間終端機狀態可能改變** → 去向在使用者選定項目的當下才重新判斷，因此標題最壞情況是短暫過時，行為仍然正確：標題說送出但屆時沒有終端機，文字仍會安全地進到剪貼簿。
- **送出指令把文字寫進使用者當下的終端機，那可能是正在跑東西的分頁** → 文字不附換行、不執行，停在輸入位置；使用者按 Enter 前隨時可刪。這是「不自動開新終端機」與「不自動執行」兩個決策共同的安全網。
